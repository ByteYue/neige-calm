Planner + Assistant: read the track's report. Returns `{ text, summary, schemaVersion, docRev, updated_at, blocks, taskDiagnostics }` in `structuredContent` (the text block is a one-line receipt: docRev, block count, bytes, summary) — `text` is the flat Markdown and `blocks` is the addressable index `[{ id, kind, rev }]` in document order; `taskDiagnostics` is the read-time DB-aware task-block schedulability result and is returned to Planner callers only (it carries dispatched-task runtime state). `select` bounds what you get back: `"full"` (default) is `text` + index; `"index"` is everything except `text` and records nothing, so it does not anchor a write (read `text` — full, blocks or sections — for that); `{ blocks: ["b_x", …] }` is the index plus a `text` holding only those blocks in document order, each preceded by its `<!-- neige:b_x -->` marker line (an unknown id is an error); `{ sections: ["H1 text", …] }` is the same for every block of those H1 sections (a section is an H1 block plus the blocks up to the next H1; an unknown section is refused with the report's sections listed). Every read that returns `text` is this session's read of the report: `calm.report.commit` anchors its ops to exactly what it returned, so you pass no revisions (`index` records nothing). The report is made of blocks (see `calm.report.blocks.kinds` for the block vocabulary). Pass `{ with_markers: true }` to get the full `text` with one `<!-- neige:b_xxxx -->` line before each block so you can see block boundaries; markers exist only in this read output (and are accepted+stripped by `calm.report.write_markdown`), they are never stored. `chart.series` and live `table` blocks carry a `resolved` summary in `blocks[i]` (`status` is `ok` | `pending` | `unavailable`; a `pending` may carry a `reason`); pass `{ resolve: { [block_id]: "full" } }` to get that block's stored points (or table rows) and `"none"` to skip it — reads never call a plugin, so a block without stored data is `pending` until a background resolution lands.
